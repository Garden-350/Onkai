# 音ズレの原因と直し方（10/23）

結論：プログラムの原因と、譜面（採譜）の原因の両方がある。どちらも直せる。

---

## A. プログラムの原因（ゲーム本体）

### A-1. ポーズしても曲が止まっていない（いちばん大きい）

Game.cpp のポーズは、譜面の時計を止めているだけで、曲（ChartObject の `sound`）を止めていない。
再開すると、譜面の時計は「ポーズしていた分」だけ戻されるのに、曲はその間も流れ続けている。
そのため、**1回ポーズするたびに、ポーズしていた秒数そのまま曲と譜面がズレる**。

ChartObject.h（public）：

```cpp
	void PauseAudio();
	void ResumeAudio();
```

ChartObject.cpp：

```cpp
void ChartObject::PauseAudio()
{
	StopLongSounds();
	if (m_AudioStarted && !m_AudioFile.empty()) sound.PauseDynamic();
}

void ChartObject::ResumeAudio()
{
	if (m_AudioStarted && !m_AudioFile.empty()) sound.ResumeDynamic();
}
```

Game.cpp のポーズ切り替え：

- `chart->StopLongSounds();` を `chart->PauseAudio();` に変える。
- 再開側の `chart->AddPauseOffset(pauseDuration);` の次の行に `chart->ResumeAudio();` を足す。

### A-2. 2回目のポーズから、再開位置がずれる（sound.cpp）

`PauseDynamic` は止めた位置を `SamplesPlayed`（再生を始めてから何サンプル鳴らしたか）で覚えている。
1回目は合うが、再開は「途中の位置から鳴らし直し」なので、2回目のポーズでは「再開してから鳴らした分」しか数えられない。
そのため、曲の頭の方へ戻ってしまう。
**エディターの sound.cpp も同じ作りなら、エディターでも2回目の一時停止から音と画面がズレる。**採譜中のズレの原因になっている可能性が高いので、両方直す。

sound.h（`m_dynamicPlayPos` の下）：

```cpp
	UINT64                m_dynamicSamplesAtStart = 0;	// PlayDynamic した瞬間の SamplesPlayed
```

sound.cpp `PlayDynamic` の `m_pDynamicVoice->Start(0);` の直後：

```cpp
	{
		XAUDIO2_VOICE_STATE st;
		m_pDynamicVoice->GetState(&st);
		m_dynamicSamplesAtStart = st.SamplesPlayed;	// ここからの増えた分だけを数える
	}
```

sound.cpp `PauseDynamic` の最後の1行を置き換え：

```cpp
	// 鳴らし始めた位置 ＋ そこから鳴らした分 ＝ 今の位置
	m_dynamicPlayPos += (UINT32)(state.SamplesPlayed - m_dynamicSamplesAtStart);
	const UINT32 blockAlign = m_dynamicWfx.Format.nBlockAlign;
	const UINT32 totalSamples = (blockAlign > 0) ? m_dynamicBuffer.AudioBytes / blockAlign : 0;
	if (totalSamples > 0) m_dynamicPlayPos %= totalSamples;	// ループして1周を超えた時用
```

### A-3. 曲の鳴り始めが、最大1フレーム遅れる

今は「譜面の時計が 0 を過ぎたフレーム」で曲を鳴らしている。
そのフレームではもう時計が 0.001〜0.016 秒くらい進んでいるので、その分だけ曲が遅れて始まる。
遅れる量は毎回バラバラ。
鳴らした瞬間に、時計をちょうど 0 にそろえる。

### A-4. 音が耳に届くまでの遅れ（調整用の値）

PC は、音を出す命令から実際に聞こえるまで 0.02〜0.05 秒くらいかかる。
音ゲーでよくある「判定調整」と同じものを、定数で用意しておく。

ChartObject.h：

```cpp
	static constexpr float kAudioLatency = 0.0f;	// 音が耳に届くまでの遅れ（秒）。「判定が早い（自分が遅れる）」と感じたら 0.02〜0.05 に
```

ChartObject::Update の時刻の計算から曲を鳴らすまで（`m_MusicTime = elapsed - m_CountInTime;` 〜 `sound.PlayDynamic();` の if の終わり）を、これに置き換え：

```cpp
	// 曲の再生位置（曲を鳴らした瞬間が 0。カウントイン中はマイナス）
	float songTime = elapsed - m_CountInTime;

	// 0 を過ぎたら曲を鳴らす。鳴らした瞬間をちょうど 0 にそろえる（フレームの区切りで遅れた分を消す）
	if (!m_AudioStarted && songTime >= 0.0f)
	{
		m_AudioStarted = true;
		m_StartClock += std::chrono::duration_cast<std::chrono::steady_clock::duration>(
			std::chrono::duration<float>(songTime));
		songTime = 0.0f;
		if (!m_AudioFile.empty())
		{
			sound.PlayDynamic();
		}
	}

	// 判定・描画に使う時計は、耳に届くまでの遅れの分だけ遅らせる
	m_MusicTime = songTime - kAudioLatency;
```

## B. エディターの原因（採譜中のズレ）

- A-2 と同じ sound.cpp の問題があれば、2回目の一時停止から音と画面がズレる。採譜中に何度も止めて置いていると、置いた位置が少しずつ曲とずれる。
- エディターの再生時刻は、毎フレーム `musicTime += elapsedTime` で足していく作りになっている。DirectX のテンプレートの StepTimer は、1フレームが 0.1 秒を超えると 0.1 秒で打ち切る。重い瞬間（読み込みなど）があると、画面の時刻だけ遅れて曲が先に進む。
  - 気になったら、止めて → 再生し直すと揃う（StartPlayback で曲の位置を musicTime に合わせ直すため）。

## C. 譜面（採譜）の原因

### C-1. グリッドの基準（Offset）が 0 のまま

w001.wav を解析した。8分・16分のリズムの山は、0秒からではなく約 0.03〜0.04 秒遅れた所に並んでいる（推定）。
グリッドに吸着させて置いたノーツは、曲より 0.035 秒くらい早くなっている可能性がある。
BPM は 160 で概ね合っているが、解析では 159.6 も候補に出た。長い曲の後半で少しずつずれるなら、BPM も疑う。

確かめ方：

1. エディターの Grid Tools で Offset を 0.035 にする。
2. グリッドの線と、曲のキック・スネアが合って聞こえるか確認する。合っていなければ、0.01 ずつ動かす。
3. 合ったら Check Grid → Snap All Notes で、全部のノーツを新しいグリッドに合わせる。ずれたら Undo Snap で戻せる。

### C-2. グリッドから外れて置かれたノーツがある

13.9〜18.4 秒あたりの最初の方のタップと、20.37 / 20.56 / 21.40 秒のタップは、グリッドに乗っていない（耳で置いた位置のまま）。
同じ区間のタップは、time（判定の時刻）と arrivalTime がずれているものが多い（最大 0.5 秒）。
ゲームの判定は time を使うので問題は出ないが、昔の3D配置で置いたノーツなので、上の Snap All Notes で一緒に揃えるのがおすすめ。

注意：Snap All Notes は、ロングの「曲がり点」の時刻までは揃えない。曲がり点は手で確認する。

## おすすめの順番

1. A-1〜A-3（ゲーム）と A-2（エディターの sound.cpp）を直す。合わせて20分くらい。
2. ポーズしないで最初から通しで遊んで、まだズレるか確認する。
3. まだズレていたら、C-1 の Offset を合わせて Snap All Notes。
4. それでも「全部のノーツが少し早い」と感じたら、kAudioLatency を 0.02〜0.04 にする。
