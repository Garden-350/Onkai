# ロングノーツの「出し方」と「曲げ方」技術まとめ（スライド用）

コード（ChartObject.cpp / ChartObject.h / LongBeamRibbon / longBeamPS.hlsl / JudgeSystem.cpp / ChartLoader.cpp）と譜面 w001.json から拾った内容。
数字はすべて今のコードの値。

---

## 0. 一言でいうと

**ロングノーツは「時間の線」を3D空間に描いたもの。**

- 奥行き（Z）＝あと何秒で判定ラインに届くか
- 横（X）＝その時刻にどのレーンにいるか

この2つで、線の上の点の位置が決まる。
曲がり点は「この時刻からこのレーン」というデータだけで、形はプログラムが作る。

---

## 1. データの持ち方

**譜面 JSON（エディターが書き出す）**

```json
{ "lane": 3, "type": 1, "arrivalTime": 31.535, "time": 37.16,
  "turns": [ {"time": 31.875, "lane": 5}, {"time": 32.25, "lane": 3}, ... ] }
```

| 項目 | 意味 |
| --- | --- |
| `arrivalTime` | 先端が判定ラインに届く時刻（押し始め） |
| `time` | 終端が届く時刻（押し終わり） |
| `lane` | 最初のレーン |
| `turns` | 曲がり点の並び。`time` の時刻から `lane` へ移る |

**読み込み（ChartLoader.cpp）**

- `turns` を `LaneTurn{time, lane}` の配列にする。
- 範囲外のレーン（0〜5 以外）は捨てる。
- 時刻順にソートする。エディターの並び順を信用しない。

**ゲーム中に使う2つの関数（ChartNote）**

- `LaneAt(t)`：t 秒の時点で線があるレーンを返す。曲がり点を前から順に見ていくだけ。
- `AcceptsLane(key, t, grace)`：t 秒にそのキーで受けてよいかを返す。
  - 曲がり点の前後 ±grace 秒は、「曲がる前のレーン」と「曲がった後のレーン」の両方を正解にする。

**収録曲 w001 での使われ方**

- ロング 38本のうち 34本が曲がる。
- 曲がり点は合計 127個。
- 一番多いロングは 1本で 14回曲がる（約5.6秒）。
  - J と L を 0.375秒（8分音符）ごとに往復する。
  - 途中で S と F の往復に移る。左右の手をまたぐ。

## 2. 出し方：どこから、どう流れてくるか

**ハイウェイ方式（kHighwayMode = true）**

ノーツは、判定円と同じ高さの平面を、奥からまっすぐ手前に来る。

読み込み時に、全ノーツの出現位置と出現時刻を上書きする。

```cpp
note.spawnPos  = judge + Vector3(0, 0, m_HighwayDepth);  // 判定円の真奥 1800
note.spawnTime = arrive - m_HighwayApproach;             // 届く 1.2秒前に出現
note.controlPoints.clear();  // ベジェ曲線をやめて直線に
note.spiralRadius = 0.0f;    // 螺旋もやめる
```

**ポイント**

- 全ノーツが同じ速さで流れる。
- エディター用の自由な軌道（ベジェ・螺旋）は、ゲームではあえて捨てている。見やすさを優先したため。

**時間 → 奥行きの変換（LongPointAt）**

```cpp
z = (tau - m_MusicTime) / m_HighwayApproach * m_HighwayDepth * highSpeed;
```

- tau は「この点が判定ラインに届く時刻」。
- 届くのが先の点ほど奥に置かれる。
- 曲が進むと、全部の点が同じ速さで手前に来る。
- ハイスピードはこの式に掛けるだけで効く。

**画面に描く範囲**

- 手前の端：`max(今, arrivalTime)`。もう受け終わった部分は描かない。判定ラインで「吸い込まれて」いくように見える。
- 奥の端：`min(time, 今 + 1.2秒)`。出現位置より奥は描かない。
- まだ奥に続いている時は、奥の端の 15% をフェードさせる。奥からにじみ出てくるように見える。
- 床から 4 だけ浮かせる。床とのちらつき（Zファイティング）を防ぐため。

## 3. 曲げ方

**考え方**

- 曲がりは「形」ではなく「時刻」で持つ。
- 線の上の点ごとに、「その点が判定ラインに届く時刻 tau に、どのレーンにいるか」を計算する。
- Z は時刻で決まっている。だから曲がり点は、時間軸上の折れ目として、そのまま奥から流れてくる。

**横の位置の計算（LongPointAt）**

```cpp
constexpr float kTurnBlend = 0.06f;            // 曲がりにかける秒数
for (const auto& tr : n.turns) {
    if (tau < tr.time) break;
    float from = 今のレーンのX, to = 次のレーンのX;
    float k = clamp((tau - tr.time) / kTurnBlend, 0, 1);
    k = k * k * (3 - 2 * k);                    // smoothstep
    x = from + (to - from) * k;
}
```

**ポイント**

- 直角に折ると、帯の幅が潰れて見える。そこで 0.06秒分だけ、なめらかな S 字でつないでいる。
- 補間には smoothstep を使っているので、曲がり始めと曲がり終わりが自然になる。
- 判定円の位置は毎フレーム `m_JudgeCircles[lane].GetPosition(今)` から取る。判定円が動いても線がついてくる。
- 色も `GetLaneColor(LaneAt(tau))` で点ごとに決める。曲がった先から、色がそのレーンの色に変わる。
  - S / J = 赤、D / K = 青、F / L = 緑。

**曲がり点の音（UpdateLongSounds）**

- 曲がり点の時刻を過ぎた時に、押していれば 1回だけ鳴らす（SOUND_CLAMPU）。
- `nextTurnIndex` で、どこまで鳴らしたかを覚えておく。二重に鳴らないようにするため。

## 4. 描き方：光の帯（LongBeamRibbon）

**流れ**

1. 0.01秒ごとに、線の上の点を打つ（`kStep`）。手前から奥へ並べる。
2. 点ごとに、線の向きとカメラへの向きの外積から「横」を求める。
   - その横に左右2つの頂点を作る。どの角度から見ても、帯が正面を向く（ビルボード帯）。
3. 頂点を三角形ストリップでつなぐ。**1本を1回の描画命令で描く。**

```
  L0──L1──L2──L3      ← 点ごとに左右2頂点
  │ ╲ │ ╲ │ ╲ │
  R0──R1──R2──R3      ← TRIANGLESTRIP で1回で描く
```

**工夫**

- UV の v を「線に沿った距離 ÷ 帯の幅」で連続させている。四角を並べた時のような継ぎ目が出ない。
- 頂点バッファは最大 512点分を最初に確保する。毎フレーム中身だけ書き換える（Modify）。
- 頂点はすでにワールド座標なので、World 行列は単位行列にしている。
- 描画の設定
  - 加算合成
  - 深度テストはするが、深度は書かない（半透明の光のため）
  - 裏面を消さない（CULL_NONE）

**ピクセルシェーダー（longBeamPS.hlsl）**

```hlsl
float d    = abs(uv.x - 0.5) * 2;   // 帯の中心0 〜 端1
float core = exp(-d*d*6);           // 細く強い芯
float glow = exp(-d*d*1);           // 太く柔らかい光
float n    = noise(uv.x*0.6, uv.y*0.12 + time*1.5);  // 線に沿って流れる揺らぎ
color = 白寄りのレーン色 * core * 1.8 + 紫の光 * glow * 0.8 * (0.7 + 0.6*n);
```

- ガウス関数を2つ重ねて、「芯」と「にじみ」を1枚で表現している。
- ノイズテクスチャを曲の時間でずらしている。エネルギーが線を流れるように見える。

**押せていない時の見た目**

- 灰色にする。
- 帯の幅を 90 から 60 に細くする。
- 明るさを 1.0 から 0.35 に下げる。

このため、離したことがすぐ分かる。

## 5. 判定のしくみ

**チェックポイント（tick）方式（JudgeSystem::JudgeLongNoteHold）**

- 先端が届いた時刻から、0.2秒ごとにチェックする（`kLongTickInterval`）。
- 最後のチェックは、必ず終点の時刻ちょうどに合わせる。
- 各チェックでは、その時刻に正しいキーが押されているかを見る。
  - 押されていれば PERFECT。
  - 離していれば MISS。
- 曲がり点の前後 ±0.12秒（`kTurnGrace`）は、前と後のレーンのどちらのキーでもよい。指を押し替える瞬間に、MISS にならない。
- チェックの数は、読み込み時に数えて総ノーツ数に入れている（`CountLongNoteCheckPoint`）。リザルトの計算が合うようにするため。

**押し始め**

- 「届いた瞬間に押した（Trigger）」ではなく、「届いた時に押している（Press）」で判定する。
- 少し早めに押しておいてもよい。

**フレームが飛んでも抜けない**

- `while (今 >= 次のチェック時刻)` で回している。
- 処理落ちで時間が飛んでも、間のチェックをまとめて処理する。

## 6. 押している間の手ごたえ

| 演出 | 中身 |
| --- | --- |
| バリア | 判定円にレーン色の障壁の板を出す。sin で脈打つ（0.75 ± 0.15） |
| 粉パーティクル | 押しているレーンの判定円から、0.04秒ごとに1粒。レーン色で、ふわっと落ちる |
| 光の柱・コンボ | チェックごとに RegisterHit。叩いた時と同じ反応を返す |
| 曲がりの音 | 曲がり点で1回鳴る |
| 押し切り | 敵に「HP の4割 ÷ ロングの本数」のダメージ（カウンター） |
| 押し切りの視線 | 世界側のカメラだけを 3度見上げて戻す（0.15拍で上がり、0.4拍から戻る） |

設計の意図（企業フィードバック #5「ロングを押している間が暇」への答え）

- 押している間ずっと、光・粉・音で反応が返ってくる。
- 押し切った瞬間に敵を削る「とどめ」がある。
- カメラは世界側のレイヤーだけを動かし、譜面（判定円）は動かさない。見やすさを守るため。

## 7. Before / After（改善の流れ）

**旧方式：3つの3Dモデルを並べる（DrawLongNotes。kHighwayMode = false で今も残っている）**

- 3つのパーツ
  - 先端（sentan）
  - 本体の鎖（dou）を 0.01秒間隔で敷き詰める
  - 終端の輪（o）
- 各パーツを進行方向に向ける回転行列（noteBasis）を、外積から作っていた。
- 押している間は、先端を判定ラインで止めて、障壁で「せき止めて」いるように見せていた。
- 問題点
  - 1本で最大 120回前後の描画命令（鎖 60 ＋ 光 60 など）。
  - 本数に上限があるので、長いロングだと鎖がスカスカになる。
  - 鎖の継ぎ目が見える。
  - 曲がる線が作りにくい。

**新方式：光の帯（DrawHighwayLongNotes ＋ LongBeamRibbon）**

- 1本 1回の描画命令。
- 0.01秒ごとの点を最大 512点まで使えるので、なめらか。
- 継ぎ目がない。
- 点の位置を計算で決めるだけなので、曲がりも簡単に入る。

| | 旧：モデル方式 | 新：光の帯 |
| --- | --- | --- |
| 描画命令／1本 | 最大 約120回 | 1回 |
| 継ぎ目 | 出る | 出ない（UV が連続） |
| 曲がり | 難しい | 時刻とレーンのデータだけで描ける |
| 見た目の調整 | モデルとテクスチャ | シェーダーの数字 |

## 10. スライド構成案（7枚）

1. **ロングノーツ＝時間の線**：奥行き＝時間、横＝レーン。図を1枚。
2. **データ**：JSON の `turns` と、`LaneAt` / `AcceptsLane`。w001 では 38本中 34本が曲がる。
3. **出し方**：ハイウェイ方式、時間 → 奥行きの式、描く範囲と奥のフェード。
4. **曲げ方**：smoothstep で 0.06秒かけて曲げる。色も曲がり先で変わる。
5. **描き方**：ビルボード帯、三角形ストリップで1回描画、シェーダーの芯とにじみ。
6. **判定と手ごたえ**：0.2秒チェック、曲がり前後 0.12秒の猶予、バリア・粉・押し切りダメージ・視線。
7. **Before / After**：描画 120回 → 1回、継ぎ目なし、曲がりが可能に。

スライド 1・4・5 は、ゲーム画面のスクリーンショットか、短い GIF があると伝わりやすい。

## 11. 調べていて気づいたこと（発表の前に直すと安心）

1. **バリアが曲がりについてこない**
   - バリアの「押しているか」の判定（ChartObject.cpp 1490行付近）が、`note.lane`（最初のレーン）と `kLaneKeys[note.lane]` を見ている。
   - そのため、曲がった後は、正しいキーを押していてもバリアが出ない。
   - 粉パーティクルの方は `LaneAt(m_MusicTime)` を使っているので正しい。
   - 直し方：バリアの方も粉と同じく `int ln = note.LaneAt(m_MusicTime);` を使い、`holding[ln]` と `kLaneKeys[ln]` にする。
2. **曲がりの音が詰まる**
   - 今の曲がり音は `SOUND_CLAMPU` で、間隔の制限がない。
   - 曲がり点が続く所では、音が重なって遅れて聞こえることがある。
   - 曲がり専用の音（`SOUND_LONG_TURN`）を用意して、前に鳴らしてから 0.06秒たっていなければ鳴らさない（`kTurnSeMinInterval`）ようにすると直る。
