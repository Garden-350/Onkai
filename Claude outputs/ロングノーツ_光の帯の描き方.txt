==============================================================
  ロングノーツ「光の帯」の描き方（仕組みの説明）
==============================================================

関係するコードは次のとおり。

  ChartObject.cpp  DrawHighwayLongNotes()  … 点を打つ
                   LongPointAt()           … 点の位置を計算する
  LongBeamRibbon.cpp  Draw()               … 点を帯にして描く
  shader/longBeamVS.hlsl                   … 頂点シェーダー（ほぼ素通し）
  shader/longBeamPS.hlsl                   … ピクセルシェーダー（光らせる）


■ 0. ひとことで
--------------------------------------------------------------
今のロングノーツは、3Dモデルを並べていない。
毎フレーム、次の3つを順にやっている。

  ① 線の上に、細かく点を打つ（0.01秒ぶんごとに1個）
  ② 点を左右に広げて、細長い「帯」のポリゴンを作る
  ③ その帯を、シェーダーで光らせて描く

「点の位置」を計算で決めているだけなので、曲がっていても同じやり方で描ける。


■ 1. 毎フレームの流れ
--------------------------------------------------------------
DrawHighwayLongNotes() が、ロング1本ごとに次のことをする。

  1) 見えている範囲を決める
       from = max(今の時刻, arrivalTime)       … 手前の端
       to   = min(time,     今の時刻 + 1.2秒)  … 奥の端
     手前の端：もう受けた部分（判定ラインより手前）は描かない。
     奥の端　：出現位置（1.2秒先）より奥は描かない。

  2) from から to まで、0.01秒ごとに点を打つ（kStep = 0.01）
     点ごとに次の3つを決める。
       位置 … LongPointAt(note, その時刻)
       色　 … その時刻のレーンの色（曲がった先は、そのレーンの色）
       濃さ … 奥の端の近くだけ薄くする（奥からにじみ出て見える）

  3) 点の列を LongBeamRibbon::Draw() に渡す
     → 帯にして、1回で描く


■ 2. 点の位置の決め方（LongPointAt）
--------------------------------------------------------------
線の上の点には、それぞれ「判定ラインに届く時刻 tau」がある。

  奥行き（Z）
    z = (tau - 今の時刻) / 1.2秒 × 1800 × ハイスピード

    tau = 今の時刻   なら z = 0（判定ラインの上）
    tau = 今 + 1.2秒 なら z = 1800（出現位置）

    時間が進むと (tau - 今) が小さくなるので、点は手前に来る。
    「点を動かしている」のではない。毎フレーム式で計算し直しているだけ。

  横（X）
    tau の時点で線があるレーンの、判定円の X。
    曲がり点をまたぐ所は、0.06秒かけて smoothstep でなめらかに移す。

  高さ（Y）
    判定円の高さ ＋ 4（床とちらつかないように、少し浮かせる）

  上から見た図（↓が手前、判定ライン側）

        奥（出現位置 z=1800）
           │
           │      ← tau が大きい点ほど奥
           │
           └──┐   ← 曲がり点（0.06秒ぶんで斜めにつなぐ）
              │
              │
        ──────●──────  判定ライン（z=0）
        手前


■ 3. 点 → 帯（LongBeamRibbon::Draw）
--------------------------------------------------------------
GPU は三角形しか描けない。
そこで、点を左右に広げて頂点を2つ作り、三角形でつないで帯にする。

【3-1】点ごとに「横の向き」を求める

  進む向き  dir  = (次の点 - 前の点) を正規化
  カメラへ  toCam = (カメラの位置 - この点)
  横の向き  side = dir × toCam（外積）を正規化して、帯の幅の半分をかける

  外積の答えは「2つのベクトルの両方に垂直な向き」になる。
  そのため side は、次の2つを満たす。
    ・線に垂直 → 帯の横幅の方向になる
    ・カメラへの向きにも垂直 → カメラから見て、必ず横に広がって見える

  この「いつもカメラの方を向く板」のことを、ビルボードという。
  床に平らな板を置くだけだと、斜めから見ると細く見え、真横から見ると消える。
  カメラの方を向けておけば、どの角度から見ても同じ太さに見える。

【3-2】左右2つの頂点を作る

  L = 点 - side      （左の頂点）
  R = 点 + side      （右の頂点）

         L0    L1    L2    L3
         ●─────●─────●─────●
     点  ○     ○     ○     ○      ← 線の上の点
         ●─────●─────●─────●
         R0    R1    R2    R3

【3-3】三角形ストリップでつなぐ

  頂点を L0, R0, L1, R1, L2, R2 … の順に並べる。
  TRIANGLESTRIP は、隣り合う3つの頂点で次々に三角形を作る描き方。

    (L0,R0,L1) (R0,L1,R1) (L1,R1,L2) (R1,L2,R2) …

         L0────L1────L2
         │ ╲   │ ╲   │
         │   ╲ │   ╲ │
         R0────R1────R2

  点が n 個なら、頂点 2n 個・三角形 2n-2 枚。
  これを ctx->Draw(n * 2, 0) の1回で描く。

  例：ロング1本が画面いっぱい（1.2秒ぶん）に見えている時
      点 121個 → 頂点 242個 → 三角形 240枚 → 描画命令 1回

【3-4】UV（テクスチャ座標）の付け方

  u（横）：左の頂点 = 0、右の頂点 = 1
  v（縦）：手前からの「線に沿った距離 ÷ 帯の幅」

  v は点から点へ途切れずに増えていく。
  そのため、模様が帯全体でひと続きになり、継ぎ目が出ない。
  四角を何枚も並べる方式だと、1枚ごとに UV が 0〜1 に戻るので継ぎ目が見える。

【3-5】頂点バッファの使い方

  ・Init() で、512点ぶん（1024頂点）の頂点バッファを先に作っておく。
  ・Draw() のたびに中身を書き換えて、Modify() で GPU に送る。
    毎フレーム作り直すより速い。
  ・頂点にはもうワールド座標が入っているので、World 行列は単位行列にする。
    移動も回転もしない。


■ 4. 光らせ方（longBeamPS.hlsl）
--------------------------------------------------------------
帯は、ただの細長いポリゴン。
「光っている」ように見えるのは、ピクセルシェーダーで明るさを決めているから。

【4-1】帯の中心からの距離

  d = |u - 0.5| × 2      … 中心で 0、両端で 1

【4-2】芯 と にじみ を重ねる

  core = exp(-d² × 6)    … 細くて強い芯
  glow = exp(-d² × 1)    … 太くて柔らかい光

  帯を横に切った時の明るさ

    明るさ
     1 ┤        ╭╮          core（細い山）
       │      ╭─╯╰─╮
       │   ╭──╯ ╱╲ ╰──╮     glow（なだらかな山）
     0 ┼───┴───────────┴──
       左端    中心    右端

  exp(-d²) は「ガウス関数」。中心が一番明るく、外に行くほどなめらかに暗くなる。
  2つを足すと、「白く光る芯のまわりに、色のついた光がにじむ」見た目になる。

【4-3】流れる揺らぎ

  n = noise.png を (u×0.6, v×0.12 + 時間×1.5) で読む
  energy = 0.7 + 0.6 × n

  時間でずらして読むので、模様が線に沿って流れる。
  エネルギーが流れているように見える。

【4-4】色を決める

  芯の色　 = レーン色を白に 6割寄せた色
  外側の色 = 紫の光（ChartObject で指定。0.6, 0.35, 1.0）

  color = 芯の色 × core × 1.8 ＋ 外側の色 × glow × 0.8 × energy
  color = color × intensity（明るさ。押していない時は下げる）
  α     = 頂点の濃さ（奥のフェード用）

【4-5】描く時の設定

  加算合成（BS_ADDITIVE）
    画面の色 ＝ 今ある色 ＋ この色 × α
    ・黒い所は何も足さないので、透明と同じになる。帯の端が自然に消える。
    ・重なると明るくなるので、光らしく見える。

  深度テストはする、深度は書かない（SetDepthEnable(false)）
    ・テストはする：手前にある物（判定円など）の後ろには隠れる。
    ・書かない：光同士が重なった時に、後から描いた光が消されない。

  裏面も描く（CULL_NONE）
    ・帯の頂点の並び順は、カメラとの位置関係で表と裏が入れ替わることがある。
      どちら向きでも消えないように、裏面も描く。


■ 5. 押している時 / 押していない時
--------------------------------------------------------------
                    押している     押していない
  色                レーン色       灰色（0.4）
  帯の幅            90             60
  明るさ intensity  1.0            0.35

  「押している」かどうかは、今の時刻に線があるレーンのキーを押しているかで決める。
  曲がり点の前後 0.12秒は、前と後のどちらのキーでもよい。


■ 6. 前の方式（3Dモデルを並べる）との違い
--------------------------------------------------------------
                      前：モデルを並べる          今：光の帯
  作り方              先端・鎖・輪の3つのモデルを  点を打って、帯のポリゴンを
                      ずらしながら何個も描く        その場で作る
  描画命令（1本）     最大 約120回                  1回
  継ぎ目              鎖のつなぎ目が見える          出ない（UV がひと続き）
  曲がり              モデルの向きを全部合わせる     点の位置を変えるだけ
                      必要があり、難しい
  見た目の調整        モデルとテクスチャを作り直す   シェーダーの数字を変える

  前の方式（DrawLongNotes）は、ChartObject.h の kHighwayMode を false にすると、今も使える。


■ 7. 見た目を変えたい時にいじる所
--------------------------------------------------------------
  変えたいこと              場所                                変え方
  ------------------------  ----------------------------------  ----------------------
  帯の太さ                  DrawHighwayLongNotes の 90.0f / 60.0f  大きくすると太い
  なめらかさ                kStep（0.01）                         小さいほどなめらか
                                                                  （点は512個まで）
  外側の光の色              kGlowColor（0.6, 0.35, 1.0）          RGB
  芯の細さ                  longBeamPS の core の 6.0             大きいほど細い
  にじみの広さ              longBeamPS の glow の 1.0             小さいほど広い
  芯の白さ                  longBeamPS の lerp の 0.6             1 で真っ白、0 でレーン色
  流れる速さ                longBeamPS の time * 1.5              大きいほど速い
  模様の細かさ              longBeamPS の tex.y * 0.12            大きいほど細かい
  曲がりの急さ              LongPointAt の kTurnBlend（0.06）     小さいほど直角に近い
  奥のフェードの長さ        DrawHighwayLongNotes の 0.15          大きいほど長く薄くなる
