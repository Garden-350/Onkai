# 弱点をキーの画像で出す・ビームはど真ん中へ 組み込みガイド

`2_弱点の見やすさ` の内容もこの中に全部入っている。`2_` はまだ組み込んでいなければ飛ばして、こちらだけ組み込めばよい。

## 0. 今回の仕様

| 項目 | 中身 |
| --- | --- |
| 弱点 | 「どのキーか（S D F J K L）」と「敵の体のどこか」の2つを持つ。4小節ごとに、キーも場所もランダムで変わる（前と同じキー・近すぎる場所にはしない） |
| 弱点の見た目 | 弱点の場所に、そのキーの画像（S.png など、判定円のアイコンと同じもの）を出す。後ろに六角形、まわりに残り時間の輪（真上から時計回りに減る）。変わった瞬間はキーの画像が大きく出て縮む。拍ごとに少し膨らむ |
| 判定円の印 | 弱点のレーンの判定円を、レーン色と金の中間の六角形と残り時間の輪で囲む |
| 普段の攻撃 | どのレーンを叩いても、光は弱点の場所へ飛ぶ。弱点のキーで叩くと、光が太く明るく金色になり、ダメージ2倍、着弾も派手 |
| 必殺技 | 発動時に弱点を選び直し、撃つまで固定。レーンのキーで狙いを選び（判定円に枠が出る）、Space でロック。**ビームは必ず敵のど真ん中へ飛ぶ**。狙いが弱点のキーと合っていれば大ダメージと大きな演出、違えば防がれる |
| 狙いのヒント | 狙いが弱点のキーと合っている時は、判定円の枠が金色になり、敵の弱点にも枠が出る（`kShowMatchHint` で消せる） |

前回あった「敵のまわりに6つの部位を冠の形に並べる」はなくなった（弱点は1つだけが、ランダムな場所に出る）。

## 1. ファイルを置き換え

`1_新規ファイル` の6つで、プロジェクトの同じ名前のファイルを置き換える。

- `WeakPoint.h` / `WeakPoint.cpp`（今回の本体）
- `AttackOrbs.h` / `AttackOrbs.cpp`（普段の光を細く暗く、弱点への光を太く明るく）
- `ImpactFx.h` / `ImpactFx.cpp`（弱点でない所の着弾を小さく暗く）

`GetPoint` という関数はなくなり、代わりに `GetWeakPos`（弱点の場所）になった。ChartObject で `GetPoint` を使っている2か所は、下の手順で直す。

## 4. 調整する所（WeakPoint.h）

| 変えたいこと | 名前（今の値） |
| --- | --- |
| 弱点が変わる間隔 | `kBarsPerSwitch`（4小節） |
| 弱点が出る範囲（敵の中心からの距離） | `kPosRadiusMin`（30）〜 `kPosRadiusMax`（150） |
| 前の場所からどれだけ動かすか | `kPosMinMove`（90） |
| 出る範囲を上下にずらす | `kPosLift`（30） |
| 敵の体に埋もれる時 | `kPosFront`（120）を大きく |
| キーの画像の大きさ（画面のピクセル） | `kKeyIconSize`（72） |
| 出た瞬間の大きさ | `kKeyIconPop`（0.5 で 1.5倍から縮む。0 で弾まない） |
| 六角形と残り時間の輪の大きさ | `kWeakRadius`（46）、`kTimerRadius`（62） |
| 拍ごとの膨らみ | `kBeatKick`（0.15。0 で膨らまない） |
| 赤くなり始める残りの割合 | `kWarnRatio`（0.25） |
| 判定円の印 | `kShowLaneMarker`、`kLaneMarkerRadius`（72）、`kLaneMarkerAlpha`（0.85） |
| 狙いのヒントをやめる | `kShowMatchHint` を false |

キーの画像は画面のピクセルで、六角形と輪は3Dの大きさで決めている。敵までの距離で見え方の比が変わるので、画像が輪からはみ出したり、輪が大きすぎたりしたら、`kKeyIconSize` か `kTimerRadius` で合わせる。

## 5. 確認すること

1. 曲が始まると、敵の体のどこかにキーの画像が出て、4小節ごとに別のキー・別の場所へ変わるか。
2. どのレーンを叩いても、光がキーの画像の所へ飛ぶか。弱点のキーで叩いた時だけ太く金色か。
3. 弱点のレーンの判定円が六角形で囲まれているか。
4. 必殺技：狙いの枠が判定円に出て、弱点のキーと合うと金色になり、敵の方にも枠が出るか。ビームが敵の真ん中に飛ぶか。

## 6. 気をつけること

- **キーの画像の位置がずれる場合**：画像は、3D の位置を画面の位置に計算し直して 2D で描いている。計算にはカメラの行列（`GetViewMatrix`、`GetProjectionMatrix`）を使っている。もし画像が弱点の六角形からずれて出たら教えてください（ChartObject の判定ランクの表示と同じ計算方法に切り替えます）。
- **ランク S の画像と、キー S の画像が同じファイル**：ScoreRule の表は `assets/texture/S.png` をランク S の画像にしているが、これは判定円のキーの画像と同じファイル。ランクの画像を作る時は、`rank_S.png` のように別の名前にして、ScoreRule.h の表も直す。
