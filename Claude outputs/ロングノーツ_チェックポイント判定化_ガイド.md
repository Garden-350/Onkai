# ロングノーツ：チェックポイント判定化 実装ガイド

## 何を変えるか

今までの「arrivalTimeで一発キャッチ→押しっぱなし判定」をやめて、

```
arrivalTime(生成点) → 点 → 点 → ・・・ → time(終点)
```

のように `kLongTickInterval`（デフォルト0.2秒）間隔でチェックポイントを並べ、**各チェックポイントを完全に独立して判定**します。

- チェックポイントの瞬間にキーを押していれば → パーフェクト扱いでコンボ加算
- 押していなければ → ミス扱いでコンボが0に戻る（が、ロングノーツ自体は終わらない）
- 次のチェックポイントでまた押していれば、どんなに間が空いていてもパーフェクトで復帰

つまり「生成点で取り損ねたら最後まで詰み」という状態がなくなります。

チェックポイントの間隔(`kLongTickInterval`)は**固定秒数**なので、ハイスピード設定など見た目の速度を変えても、チェックポイント数＝コンボ数は絶対に変わりません（音楽時間だけを見て機械的に生成しているため）。

「総ノーツ数（フルコンボの基準）」も、この同じ間隔を使って自動的に数え直すようにしたので、`kLongTickInterval`の値を後から調整しても、フルコンボの基準とのズレは発生しません。

**副作用として、ロングノーツを含む曲ではPerfect数・Miss数がこれまでよりかなり増えます**（1本のロングノーツが複数回の判定に分かれるため）。リザルト画面の見た目には影響ないはずですが、一応認識しておいてください。

## 2. `JudgeSystem.cpp` — `JudgeLongNoteHold` を丸ごと置き換え

**変更前：**
```cpp
void JudgeSystem::JudgeLongNoteHold(std::vector<ChartNote>& notes, float musicTime)
{
	for (auto& n : notes)
	{
		if (!n.IsLong()) continue;
		if (n.judged) continue;

		if (n.lane < 0 || n.lane >= 6) continue;
		bool isDown = Input::GetKeyPress(kLaneKeys[n.lane]);

		// ── まだ開始していない場合 ──
		if (!n.longStarted && !n.longFailed)
		{
			float diff = n.arrivalTime - musicTime;
			if (isDown && fabsf(diff) <= kGud)
			{
				float absDiff = fabsf(diff);
				int rank = (absDiff < kPerfect) ? 0 : (absDiff < kGreat) ? 1 : 2;
				if (rank == 0) m_Perfect++;
				else if (rank == 1) m_Great++;
				else m_Good++;
				RegisterHit(n.lane, rank);

				n.longStarted = true;
				//n.nextTickTime = n.arrivalTime + kLongTickInterval;
			}
			else if (diff < -kGud)
			{
				// 開始を逃した → Failed扱いにするだけ。ノーツはendTimeまで残す
				n.longFailed = true;
				m_Miss++;
				RegisterMiss();	//コンボを切る
			}
		}
		// ── 開始済み・まだ成功継続中 ──
		else if (n.longStarted && !n.longFailed)
		{
			if (!isDown)
			{
				n.longFailed = true;
				m_Miss++;
				RegisterMiss();	//コンボを切る
			}
		}

		// ── 終了時刻に到達したら、ここで初めて judged=true にする ──
		if (musicTime >= n.time)
		{
			n.judged = true;
		}
	}
}
```

**変更後：**
```cpp
void JudgeSystem::JudgeLongNoteHold(std::vector<ChartNote>& notes, float musicTime)
{
	constexpr float kEps = 0.0001f;
	for (auto& n : notes)
	{
		if (!n.IsLong()) continue;
		if (n.judged) continue;
		if (n.lane < 0 || n.lane >= 6) continue;

		bool isDown = Input::GetKeyPress(kLaneKeys[n.lane]);

		// arrivalTime〜timeの間、kLongTickInterval間隔で並んだチェックポイントを
		// 1つずつ判定する。各チェックポイントは完全に独立していて、
		// 前のチェックポイントを逃していても次のチェックポイントでまた
		// パーフェクト扱いで復帰できる（＝ロング全体が強制ミスになることはない）。
		// 1フレームで複数のチェックポイントを跨いだ場合もwhileでまとめて処理する。
		while (musicTime >= n.nextTickTime - kEps)
		{
			bool isFinalTick = (n.nextTickTime >= n.time - kEps);

			if (isDown)
			{
				m_Perfect++;
				RegisterHit(n.lane, 0);
			}
			else
			{
				m_Miss++;
				RegisterMiss();	//コンボを切る（次のチェックポイントで復帰可能）
			}

			if (isFinalTick)
			{
				n.judged = true;
				break;
			}

			n.nextTickTime += kLongTickInterval;
			if (n.nextTickTime > n.time - kEps)
				n.nextTickTime = n.time; // 最後は必ずtime(終点)をチェックポイントにする
		}

		// 保険：何らかの理由でチェックポイントが尽きないまま終了時刻を過ぎた場合
		if (!n.judged && musicTime >= n.time - kEps)
			n.judged = true;
	}
}
```

## 動作確認のポイント

- ロングノーツの生成点（arrivalTime）で押していなくても、途中の判定点で押せばそこからパーフェクトで復帰し、コンボが伸びていくこと
- 途中で離してもロング自体は消えず、次の判定点でまた復帰できること（バリア/ビームの見た目も、押している間だけ光って堰き止められ、離すと通常の色に戻って突き抜けて見えるはず）
- リザルト画面のPerfect/Miss数が、ロングノーツを含む曲では以前よりかなり増えること（仕様通り）
- フルコンボ判定（`GetMaxComboCount() == GetTotalNoteCount()`）が、`kLongTickInterval`の値を変えても崩れないこと
